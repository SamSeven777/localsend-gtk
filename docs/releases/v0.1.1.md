# LocalSend GTK v0.1.1

An AppImage packaging and update-support release for the unofficial Rust / GTK4
Linux client.

## Included in this release

- GitHub releases now include a thin AppImage and a matching
  `.AppImage.zsync` file.
- The AppImage embeds `gh-releases-zsync` update information derived from
  `GITHUB_REPOSITORY`. Gearlever and AppImageUpdate can therefore update from
  the repository that produced the release, whether it is a fork or upstream.
- `StartupWMClass=org.localsend.localsend_gtk` and the matching X11/Wayland
  application identity let Gearlever or AppImageLauncher associate the running
  window with its launcher, including dock icons and **Pin to dock**.
- XDG autostart uses the outer `.AppImage` path instead of the temporary mount,
  so **Launch at startup** keeps working after the file is closed or moved.
- The AppDir build validates its desktop entry, icon, `.DirIcon`, `AppRun`,
  AppStream metadata and update information before uploading.

## Downloads and requirements

Native **Linux x86_64** packages are provided as AppImage, DEB, RPM and tar.gz,
together with `SHA256SUMS`. They require **glibc 2.39+, GTK 4.12+ and
libadwaita 1.5+**.

The AppImage remains thin: it uses the host's GTK4/libadwaita runtime instead of
bundling a full desktop stack. The `.zsync` file adds update metadata, not GTK
libraries.

- AppImage: make it executable and run it, or let Gearlever integrate it into
  the application menu. Keep the `.AppImage.zsync` next to the AppImage if you
  manage updates manually.
- Debian/Ubuntu: `sudo apt install ./localsend-gtk_0.1.1-1_amd64.deb`
- Fedora: `sudo dnf install ./localsend-gtk-0.1.1-1.x86_64.rpm`
- Tar archive: extract it and run `sudo ./install.sh`, or
  `./install.sh "$HOME/.local"` for the current user.

Gearlever and AppImageUpdate only see an update after the GitHub release is
published; draft releases are ignored.

The repository also contains AUR and Flatpak packaging recipes. This release
does not claim publication on AUR or Flathub.

## Validation

The release workflow checks that the tag, `Cargo.toml`, `Cargo.lock` and RPM spec
versions match, then builds and verifies the AppImage, its embedded update
information, the `.zsync` metadata and all checksums. Unit tests and Clippy run
before packaging. The AppImage was smoke-tested locally under Xvfb, including
the outer `APPIMAGE` path used by autostart and desktop tools.

This is an independent project, not an official LocalSend release. Feature
parity and physical-device compatibility testing are ongoing. Thanks to the
LocalSend and localsend-rs contributors.
